3.1研究流程與整體架構

本研究採 Supervised Learning（監督式學習）的 Binary Classification（二元分類）架構，先定義研究問題與 Target，再進行 Data Understanding、Data Cleaning、Feature Engineering、Feature Governance 與 Preprocessing Specification；資料規格鎖定後，才進入 Python、資料切分、正式前處理與後續 Modeling。

Research Problem→ Data Understanding→ SQL Cleaning→ Feature Engineering→ Governance / Audit→ Python Validation→ Train/Test Split→ Preprocessing→ Modeling
研究原則：研究設計與數據正確性優先於模型分數；任何可能直接或間接反映結果的欄位，都必須先經 Prediction-Time、Target Leakage、Outcome Proxy 與 Market Maturity Proxy Audit。

3.2資料來源、研究資料庫與目標變數

Raw Source

google_playstore_2026.csv：11,500 筆、15 個原始欄位。

Research Table

google_play_project.google_playstore_work：完成 3.4 後為 11,500 × 29。

Target：Success = 1 當 Installs ≥ 10,000；否則 Success = 0。Class 0 = 9,553（83.07%）、Class 1 = 1,947（16.93%），Imbalance Ratio ≈ 4.91 : 1。

本研究定位為 Cross-sectional Snapshot（單一資料快照）分類，因此 Success 表示觀察快照時點的累積安裝狀態，不宣稱固定未來時間窗的成功結果。

3.3SQL 資料處理與研究治理原則

SQL 的角色不是訓練模型，而是建立可追溯、可驗證的研究工作表。原始 15 欄加入 Success 與多個衍生特徵後形成 29 欄，全部欄位都必須被指定正式 Governance Role。

29 / 29 Governance

Feature Governance Coverage = 100%，沒有任何欄位在未經判定下進入模型。

Leakage / Proxy Exclusion

Installs、Reviews、Rating 依研究證據分別排除為 Target Leakage、Outcome Proxy、Market Maturity Proxy。

Representation Consolidation

衍生欄位取代原始字串或冗餘欄位，保留可解釋且不重複的模型表示。
