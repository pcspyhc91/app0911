App 屬性能否支援成功狀態分類？
可以建立完整分類流程，但未證明可可靠獨立預測。
現有 13 項治理特徵足以執行技術流程，但 Final Test 泛化證據有限。
哪一種候選模型較適合？
Logistic Regression｜Tuned 為 Relative Best Candidate。
「相對最佳候選」不等於 Strong Model（強模型）。
模型如何辨識成功類別？
Recall = 0.395887；Precision = 0.153539。
389 筆實際 Success=1 中辨識 154 筆，同時產生 849 筆 False Positive。
哪些特徵與模型輸出相關？
63 係數：10 正向、11 負向、42 為零。
係數只代表鎖定模型中的條件關聯，不代表 Causal Effect（因果效果）。
模型能否整合為操作介面？
可以；14/14 PASS、20/20 PASS、ACCEPTED。
功能可運作不代表模型已達生產環境效能要求。
輸出能否直接驅動正式決策？
不可以。

6.3Project Outcomes and Practical Value（專題成果與實務價值）

專題價值不以單一模型分數衡量，而由 Methodology（方法）、Data Governance（資料治理）、System Engineering（系統工程）、Interpretability（可解釋性）、Decision Governance（決策治理）與 Education（教學）共同構成。

Methodological Outcome（方法成果）

MariaDB → SQL Feature Engineering → Python Preprocessing → Stratified Split → Training-only Selection → One-time Test Evaluation。

Data Governance（資料治理）

排除 Installs、Reviews、Rating，禁止 Has_Rating，降低 Leakage／Proxy 風險。

System Engineering（系統工程）

12 組介面輸入、13 項模型欄位、63 項處理特徵與完整結果失效控制。

Governance & Risk Control（治理與風險控制）

Model Integrity、Leakage Guard、Fail-closed、Request Ownership、Human-in-the-loop。

Interpretability（可解釋性）

唯讀擷取 63 個鎖定係數，正式建立「關聯不等於因果」的解讀邊界。

Educational Value（教學價值）

誠實保留 Final Test PR-AUC 低於 No-skill 的結果，示範完整機器學習治理與失敗判讀。

Practical Value（實務價值）：形成可重現、可稽核、可操作且不掩蓋限制的 Research Prototype（研究原型）。

Limitation（限制）Observed Evidence（觀察證據）Impact（影響）
Cross-sectional Snapshot單一觀察快照不能推論固定 30／90／180 天後的未來成功。
Target DefinitionInstalls ≥ 10,000不代表營收、留存、活躍度或長期商業價值。

External Validity未使用新時間／新市場／新來源資料外部驗證生產環境穩定泛化尚未確認。
Research Boundary（研究邊界）：限制不表示研究流程無效，而是界定目前結論可以被合理解讀與使用的範圍。

6.5Future Improvement Directions（未來改善方向）

未來改善應優先處理研究設計與資料訊號，而不是直接增加模型複雜度；任何新研究都應建立新的資料版本與新的 Train／Validation／Test Governance，不得回頭反覆利用本次已開放的 Test Set。

1
Longitudinal Research Design（縱向研究設計）
建立固定預測起點與結果觀察窗，例如用上架後 30 天資料預測 90 天或 180 天結果。
2
New Prediction-time Features（新增預測時點可用特徵）
新增開發者歷史、更新頻率、商店文字與素材、支援語言、國家市場與初期行銷條件，逐欄執行 Availability／Leakage Audit。
3
Temporal and External Validation（時間與外部驗證）
保留真正未接觸的 External Test Set，檢查不同月份、年度、地區與 App 類型的穩定性。
4
Model, Imbalance and Calibration Improvement（模型、不平衡與校準改善）
在新的資料治理邊界內重新比較模型、Cost-sensitive Learning、Threshold Analysis 與 Calibration。
5
Monitoring and Model Lifecycle Governance（監測與模型生命週期治理）
建立 Input Drift、Prediction Drift、Performance Monitoring、版本與重新訓練觸發條件。
6
Interface and Decision-support Improvement（介面與決策支援改善）
增加比較模式、輸入提示、模型卡與人工覆核紀錄；在完成可靠校準前，不得把分數呈現為真實成功率。
建立縱向新資料→新增預測時點特徵→重新建模與成本敏感評估→時間外與外部驗證→機率校準與決策門檻→監測、失效與重訓治理
